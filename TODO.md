This file tracks future improvements that are **not required** for the project to reach a 10/10 quality score. They are kept here as reference for contributors who want to extend the project further.

## Future Enhancements

### High Value

- **GitHub issue and PR templates**
  Add `.github/ISSUE_TEMPLATE/` and `.github/pull_request_template.md` to standardize bug reports, feature requests, and contributions.

- **Dependency license checker**
  Add a `defence:license-check` script that scans installed packages for licenses incompatible with the project's MIT license. This strengthens supply-chain governance without adding runtime dependencies.

### Medium Value

- **End-to-end tests against the real npm registry**
  Add a small, opt-in test suite that validates `check-package-age.js` and `add-package.js` against a known, stable package on npm. These tests should be skipped by default to avoid network fragility in CI-like environments.

- **Automated README badge update**
  Replace the static "83/83 passing" test badge with a dynamic badge generated by a script or GitHub workflow. Keep in mind that CI/CD is currently out of scope for this repository.

- **Offline mode for update check**
  Add a `--offline` flag (and fallback behavior) that skips registry calls and relies solely on the local cache, preventing pre-commit hangs when the network is unavailable.

- **Historical scan tracking**
  Extend `.defence-update-check.json` to keep a short rolling history of scans, enabling detection of updates stuck in quarantine for too long or packages with unusually frequent releases.

### Low Value / Polish

- **Explanatory comment for `EventEmitter` import**
  In `tools/check-package-age.test.js`, add a short comment explaining that `EventEmitter` is used to mock HTTP request/response objects in `fetchPackageAge` tests.

- **Document environment version checks**
  Explain in the docs why defensive scripts such as `defence:reinstall` start with `node --version && npm --version` — to fail early when the environment does not match the `engines` field in `package.json`.

- **Confidence score for updates**
  Combine age, semver severity, release cadence, and presence of release notes into a simple confidence indicator (e.g., `recommended`, `review required`, `high risk`) to help developers prioritize updates.

- **Interactive update approval**
  Make `defence:update` interactive so developers can select which eligible packages to update from a checklist before applying changes.
